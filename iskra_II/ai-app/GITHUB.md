# 🔗 GitHub: почему тумблер не сработал и как сделать по-настоящему

## Что произошло с тумблером

Ты включил **Connections → GitHub** — и ничего не изменилось. Это нормально, и вот почему.

Тумблер в твоём скриншоте — это переключатель **подключённых приложений Arena**. Он даёт агенту доступ к GitHub **через специальные инструменты**. Я проверил этот канал дважды — он отвечает `unsupported`, то есть **для GitHub в этой сборке он не поддерживается**. Тумблер включён, но провода за ним нет.

Важно понимать главное: **даже при рабочем коннекторе я не смог бы пушить код в твой репозиторий сам.** Коннектор даёт чтение/создание файлов через API, но «я пишу тебе в репозиторий при каждом обновлении» — это не то, что он делает. Плюс для записи нужен твой токен, а его в переписку лучше не отправлять.

**Вывод:** обновления от меня → к тебе идут файлами. Но **публикация на сайте может быть полностью автоматической** — настроим один раз, дальше GitHub сам собирает и выкладывает. Это и есть Вариант Б.

# Вариант Б: авто-публикация (делаем один раз, ~10 минут)

Смысл: ты загружаешь файлы → **GitHub Actions сам** публикует сайт. Тебе не надо каждый раз лезть в Settings и что-то нажимать. В репозитории уже лежит готовый файл `.github/workflows/pages.yml` — он и делает всю работу.

## Шаг 1. Создать репозиторий

1. Зайди на https://github.com и войди в аккаунт
2. Справа сверху **+** → **New repository**
3. **Repository name:** `iskra` (латиницей, без пробелов)
4. Поставь **Public** (обязательно — на приватных Pages платный)
5. Галочки Add README / .gitignore **не ставь**
6. **Create repository**

## Шаг 2. Загрузить файлы

1. На странице пустого репозитория нажми **uploading an existing file** (или **Add file** → **Upload files**)
2. Открой у себя папку `ai-app` и **перетащи в браузер всё её содержимое**:
   - `index.html`
   - `app.js`
   - `manifest.json`
   - `sw.js`
   - `icon-192.png`, `icon-512.png`, `icon-512-maskable.png`
   - папку `.github` (да, её тоже — именно она включает авто-публикацию)
3. ⚠️ **Важно:** файлы должны лежать **в корне репозитория**, а не внутри папки `ai-app/`. Если после загрузки видишь `ai-app/index.html` — не то, перетащи содержимое папки, а не саму папку
4. Внизу **Commit changes**

## Шаг 3. Включить Pages через Actions

1. В репозитории: **Settings** (сверху)
2. В левом меню **Pages**
3. В блоке **Build and deployment** найди **Source**
4. Выбери **GitHub Actions** (не «Deploy from a branch»!)

Всё. Тут же начнётся первая сборка.

## Шаг 4. Забрать ссылку

1. Вкладка **Actions** (сверху). Видишь запуск «Публикация Искры на GitHub Pages» — жёлтый кружок = идёт, зелёная галочка = готово (1–2 минуты)
2. Кликни на запуск → внутри в блоке **deploy** будет ссылка на сайт
3. Или: **Settings → Pages** — сверху появится «Your site is live at **https://твой-ник.github.io/iskra/**»

Открывай — это твой ИИ в интернете, с любого устройства.

# Как теперь выходят обновления

**Первый раз** — как выше.

**Каждое следующее обновление:**

1. Я правлю файлы здесь и выдаю `ai-app.zip`
2. Ты: в репозитории **Add file** → **Upload files** → перетаскиваешь изменённые файлы → **Commit changes**
3. **Дальше ничего.** GitHub Actions видит коммит, сам пересобирает и публикует за минуту. Settings трогать не надо, кнопки нажимать не надо

**Бонус:** если что-то сломалось — вкладка **Actions** → последний запуск → видно, на каком шаге упало и почему.

**Ещё бонус:** кнопка **Run workflow** (Actions → слева выбрать workflow → справа Run workflow) пересобирает сайт вручную, если нужно.

# Если Actions не запускается

| Симптом | Причина | Что делать |
|---|---|---|
| В Actions пусто, запусков нет | Файл workflow не попал в репозиторий | Проверь, что в репозитории есть `.github/workflows/pages.yml`. На GitHub папки, начинающиеся с точки, **скрыты** — нажми «.» на клавиатуре в репозитории, откроется веб-редактор, там увидишь структуру |
| Красный крестик на запуске | В Settings → Pages не выбран **GitHub Actions** | Выбери и запусти снова (Run workflow) |
| Сайт открылся, но пустой/404 | Файлы лежат в подпапке | Перезалей так, чтобы `index.html` был в корне |
| «Actions не имеет прав» | Строгие настройки репозитория | Settings → Actions → General → Workflow permissions → **Read and write** → Save, затем Run workflow |
| Страница старая, изменений нет | Кэш браузера | Ctrl+Shift+R (жёсткое обновление) |

# Чего я сделать не могу (честно)

- ❌ **Пушить в твой репозиторий сам.** Нет доступа, и не надо его давать
- ❌ **Хранить твой GitHub-токен.** Даже если предложишь — откажусь
- ✅ **Готовить файлы так, что тебе остаётся одно перетаскивание**
- ✅ **Настроить авто-публикацию один раз** — дальше GitHub работает без тебя

Если захочешь совсем без рук — есть обходной путь на будущее: положить проект в отдельный публичный репозиторий, откуда твой репозиторий сам тянет обновления по расписанию. Но это лишний слой сложности, и в 99% случаев хватает того, что выше.
